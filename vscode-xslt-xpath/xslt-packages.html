XSLT Packages

An XSLT package is a stylesheet module whose root element is xsl:package, with a name - usually a URI - and optionally a package-version. Another stylesheet uses it by name and version, with xsl:use-package, rather than by its file path:

<xsl:package name="http://example.com/strings" package-version="2.1" version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"> ... </xsl:package> <!-- in a stylesheet that uses it --> <xsl:use-package name="http://example.com/strings" package-version="2+"/>

The package URI is an identifier, not a location: xsl:use-package matches it exactly against the name of each xsl:package, and it isn't resolved like the href of xsl:import. Neither the XSLT specification nor Saxon fixes where a package's file is.

The XSLT/XPath extension finds it, so that the package's declarations are known to the linter, auto-completion, hover help and go to definition - and when a stylesheet is run, passes the packages it uses to Saxon.

Packages in the workspace

Every .xsl and .xslt file in the workspace whose root element is xsl:package is found automatically, by the same background scan of the workspace that finds the top-level stylesheet importing a module. Its name and version are read from its xsl:package element - a package with no package-version is version 1. These packages need no setting, and they're read again when saved: change a package's name or version, and the stylesheets using it see the change.

In the XSLT specification, a stylesheet whose root element is xsl:stylesheet or xsl:transform is also a package - but one with no name, so xsl:use-package can't use it. Only modules declared with xsl:package are found here.
The workspace scan is turned off with the XSLT.resources.inferParentFromWorkspace setting. Packages are then found only from the XSLT.resources.xsltPackages setting.

Packages outside the workspace

For a package kept outside the workspace, for example a library shared between projects, add its path to the XSLT.resources.xsltPackages setting - relative to the workspace folder, or as a file: URI. The name and version are read from the file, so the path is all that's needed:

"XSLT.resources.xsltPackages": [ { "path": "../shared-xslt/strings.xsl" }, { "path": "file:///opt/xslt/dates.xsl" } ]

An entry can also give a name and version, which are then used instead of those in the file - for example, to try a copy of a package under a different version. Packages from the setting come before those found in the workspace when the same version of a package is in both.

Which version is used

When more than one file declares a package with the same name, the package-version of xsl:use-package chooses between them: the highest version in its range is used. With no package-version, the range is *, so the highest version of all is used.

package-versionVersions it matches
*any version
2.12.1 only - also written 2.1.0
2.*2, 2.0, 2.1, 2.1.5 ...
2+2 or higher
1.5 to 2.9from 1.5 to 2.9, inclusive
to 22 or lower
1.0, 3.0any of the ranges separated by commas

Versions are compared part by part as numbers, so 1.10 is higher than 1.9, and a missing part counts as 0, so 1 and 1.0.0 are the same version. A version with a name part, such as 3.0-beta, is lower than the same version without one, 3.0.

Running and debugging

When a stylesheet that uses packages is run - with Quick Run, an XSLT task for SaxonJ or SaxonC, or the debugger - the package files are passed to Saxon with its -lib option. These are the packages used by the stylesheet, by the modules it imports or includes, and by the packages themselves - each the version chosen as above. Saxon reads each package's name and version from the file, as the extension does, so packages are only ever declared in one place: the packages themselves.

Without this, Saxon reports XTSE3000 Cannot find package for each package used.

A task with a configFilename property - a Saxon configuration file - doesn't get the -lib option, as the configuration file may declare the packages itself, in its xsltPackages element. SaxonJS tasks don't get it either.

Navigating to a package

The name of an xsl:use-package is a link to the package's file - press ⌘+click to open it. Go to definition, hover help and auto-completion for the package's functions, templates, variables and other declarations work as for an imported module.
