Quick Run

Quick Run is the fastest way to run an XSLT stylesheet with Saxon (Java), without first creating a task by hand. It reuses the same command-line arguments a Saxon Task would use, but takes the stylesheet and XML source directly from the editor rather than requiring a pre-configured tasks.json entry.

Running a stylesheet

With an XSLT file open in the active editor, invoke Quick Run in one of three ways:

  • Press ⌘⌥R (Ctrl+Alt+R on Windows/Linux)
  • Click the Quick Run with Saxon play button in the editor title bar
  • Run Quick Run with Saxon from the Command Palette

The stylesheet is the active editor's file. The XML source is the current XML context file - the same file used to provide XML node-names when auto-completing XPath location steps, shown in the status bar. This means the context file now serves two purposes: XPath auto-completion, and as the Quick Run source document.

The XSLT.tasks.saxonJar setting must already point at your Saxon jar file, and an XML context file must be set, before Quick Run can be used. See the Saxon (Java) setup section on the XSLT Tasks page for how to configure the Saxon jar path.

First use: a task is created for you

The first time Quick Run is used for a given stylesheet/context-file pairing, a real task is added to your workspace's tasks.json file (creating the file if it doesn't exist yet) - not just an ephemeral, one-off run. The generated task:

  • is labelled from the stylesheet and context file names, for example demo with books.xml
  • uses the xslt-xpath.pickResultFile command for its result path, so you're prompted to choose (or reuse a recently used) output location - the same 'recent files' behaviour described on the XSLT Tasks page
  • includes an entry in its parameters array for every top-level xsl:param declared with a select default - including params declared in imported or included stylesheets - ready for you to edit
Parameter values generated this way are prefixed with ?, for example ?title. This tells Saxon to evaluate the value as an XPath expression rather than a literal string, so the generated entry reproduces the parameter's own default exactly - it does not silently override it with an empty value.

Subsequent runs

Once a task exists for a stylesheet/context-file pairing, Quick Run re-runs that same task rather than creating another one. This means you can freely edit the generated task afterwards - change a parameter value, adjust the result path, add Saxon features or additional parameters - and Quick Run will keep using your edits on every subsequent run, just like running any other task.

If you want a fresh task instead, either edit the existing one directly, or remove it from tasks.json and Quick Run will create a new one next time it's used for that stylesheet/context-file pairing.

The XML context file is remembered

Your chosen XML context file is now restored automatically when Visual Studio Code is reopened, rather than defaulting back to the last XML file you happened to view. It's stored per workspace, separately from the 'recently used' file list, so viewing other XML files - for example a transform's result - does not change what gets restored.

Quick Run currently supports Saxon (Java) transforms only. For Saxon-JS, custom parameters and features beyond what's auto-populated, chaining tasks together, or any other task configuration in detail, see the XSLT Tasks page - a task Quick Run creates is a normal task, so everything described there still applies to it.
