What's New

Highlights of the features added in releases 2.0 and 2.1:

2.1

  • Step-through debugging - debug stylesheets with SaxonJ (any edition, including Saxon-HE): breakpoints with conditions, hit counts and logpoints, stepping through templates, functions and multi-line XPath expressions - including inline functions - and the variables, context item and output so far, as you go

2.0

  • Full language support for XSLT 4.0 in Saxon 13 - type-aware auto-completion, checks, hover help and refactoring for the XSLT 4.0 and XPath 4.0 features Saxon 13 implements: new syntax and item types, keyword arguments and optional parameters, xsl:switch, and documentation notes with xsl:note
  • Code Documentation - documentation within xsl:note elements provides hover assistance using tags based on xqdoc along with Markdown descriptions. In an XSLT 3.0 stylesheet, xsl:note needs Saxon PE/EE 12.8 or later and the XSLT.validation.xslt30ItemTypesAndNotes setting.
  • Records and Enums - auto-completion, checks, hover help and refactoring for XPath 4.0 record and enumeration types, from map constructors to xsl:switch cases
  • JSON and JNodes - XPath 4.0 path expressions on JSON, with auto-completion, checks and hover help for steps on JNodes with a record type, and JNode paths shown by xdm:debug()
  • Quick Run - run the active stylesheet with a shortcut or the toolbar button, without configuring a task first - with SaxonJ, SaxonJS or the new SaxonC support
  • Inferred imports - the top-level stylesheet of a module is found from the workspace, without opening it first, and the new XSLT Imports view shows its tree of imports and includes
  • XML Catalogs - resolve the href of xsl:import and xsl:include, e.g. the http: URI of a shared library, to a local file with an OASIS XML catalog - also passed to Saxon when a stylesheet is run
  • Editing - signature help and richer hover help for functions and templates, more auto-completion, and the new Wrap with... refactoring
  • Print debugging - one auto-completed xsl:message for all the in-scope variables, formatted and colored with xdm:debug()
