XSLT 4.0

XSLT 4.0 currently comprises a set of draft proposals maintained by the W3C XSLT 4.0 Community group.

DeltaXignia's XSLT/XPath language extension provides full language support for the XSLT 4.0 and XPath 4.0 features implemented in Saxon 13, as documented here: type-aware auto-completion, checks, hover help and refactoring, as well as syntax highlighting.

Note that, given the independent release cycles for Saxon and the XSLT 4.0 draft, there will be differences between the implementation and the draft specification. Some parts of the specification are likely to change significantly before it is finalized.

We will endeavour to keep this extension up to date with the latest Saxon XSLT 4.0 implementation. Earlier versions of XSLT 4.0 will not be supported for auto-completion and linting.

Editing XSLT 4.0

The version attribute on the stylesheet root element controls the XSLT version supported by the linter and for auto-completion. When the version attribute on the stylesheet root element is set to 4.0, auto-completion for XSLT instructions and attributes and XPath functions will be included. In an XSLT 3.0 stylesheet, the linter reports XPath 4.0 syntax as an error.

For Saxon PE or EE 12.8 or later, run with syntax extensions, XSLT 4.0 item types - with record and enumeration types - and xsl:note can also be enabled in XSLT 3.0 stylesheets: see XSLT 4.0 Item Types and Notes in XSLT 3.0.

XPath files, with the .xpath extension, are always treated as XPath 4.0.

XSLT 4.0 support

The syntax highlighter, linter and auto-completion support:

  • New XPath 4.0 syntax - the pipeline -> and mapping arrow =!> operators, the method call operator =?>, e.g. $shape =?> area() - with the fields of a record type suggested after it - the × and ÷ operators, braced if expressions, map constructors without the map keyword, string templates, and the new -or-self axes
  • Literals and bindings - hexadecimal and binary numeric literals, and _ digit separators, e.g. 0xFF_FF, 0b101 and 1_000_000; QName literals, e.g. #xs:integer; positional variables, e.g. for $x at $i in $items return ...; for key and value map bindings, e.g. for key $k value $v in $map return ...; and typed for, let and some bindings, e.g. let $n as xs:integer := 3
  • New item types - choice types, such as (xs:date | xs:time), and the enum, record, fn and jnode types
  • Named item types - declared with xsl:item-type, with checks on the names used, go to definition and find references
  • Function syntax - fn and focus functions, keyword arguments such as ex:area(scale := 2), optional parameters (xsl:param required="no") and partial function application
  • Functions in no namespace - an xsl:function name without a prefix, e.g. name="double", called as double(2) - a Saxon 13 extension, not available in Saxon-HE. A function with the name and arity of a built-in function, e.g. count, replaces it in calls without a prefix, so is reported as a warning.
  • JNodes - path expressions on trees of maps and arrays, with jtree(), jkey(), jvalue() and get(...) steps
  • New instructions - snippets for xsl:switch, xsl:array and xsl:select, template rules declared within an xsl:mode (enclosed modes), and xsl:record, with its attributes completed and checked against the record type - see Building records

Features in the XSLT 4.0 draft that Saxon 13 doesn't implement - such as extensible record types - are reported by the linter.

Some of the more significant XSLT 4.0 features have their own pages:

  • Records and Enums - auto-completion, checks and refactoring for record and enumeration types, including xsl:switch on an enumeration
  • JSON and JNodes - path expressions on JSON, with auto-completion, checks and hover help for JNodes with a record type
  • Code Documentation - documenting functions and templates with xsl:note, for hover help and signature help

Running XSLT 4.0

XSLT 4.0 stylesheets run with Quick Run, or with an XSLT task. Saxon needs the --allowSyntaxExtensions:on configuration property for XPath 4.0 syntax. This is controlled by the allowSyntaxExtensions40 task property:

  • auto (the default) - on, unless the Saxon jar file, or SaxonC path, is for Saxon-HE
  • on - always on
  • off - never on
The free Saxon-HE version does not support the language extensions for XSLT 4.0. You will need to reference a Saxon-PE or Saxon-EE Jar file (with license file) in the saxonJar property of the task definition, or the equivalent SaxonC edition.

Other Editors for XSLT 4.0

The Oxygen XML editor also provides language support for XSLT 4.0, with its own bundled Saxon implementation.

While Oxygen does need to be purchased, it has the advantage of including Saxon-EE built-in, so you will not need to purchase Saxon separately. Oxygen XML provides an integrated solution for XML developers and content authors, and hosts an array of other features.
