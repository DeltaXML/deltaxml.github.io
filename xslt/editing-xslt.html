Editing XSLT in VS Code

Most XSLT mistakes are small: a misspelled type, a variable that isn't in scope, a function called with the wrong number of arguments, an element name that doesn't exist in the input. A good XSLT editor finds these while you type, not when a transformation fails - or worse, quietly produces the wrong output.

Checking as you type

In Visual Studio Code the XSLT/XPath extension checks a stylesheet continuously. It looks at the XSLT instructions and at the XPath inside attributes and text value templates, and reports unresolved variables, wrong types, record fields that don't exist, wrong numbers of function arguments, and unused variables and parameters. Problems appear as squiggles in the editor and in the Problems view, many with a quick fix. Because references are followed across xsl:import and xsl:include, a function declared in another module is found.

Completion and help that know your XML

Auto-completion is context-aware: it offers the instructions and attributes that are valid where you are, the functions and variables in scope, and - when you tell the editor which XML file you are developing the stylesheet for - the node names that actually occur in that file. Hover and signature help show a function's parameters and types, and the documentation notes you or your team have written.

Finding your way around

Stylesheets grow. Go to Definition, Peek and Find All References work for templates, functions, variables, modes, keys and more, across modules; a call hierarchy shows what calls a function or template, and the outline and breadcrumbs show where you are. Import and include hrefs are links, and a view shows the whole tree of modules for a stylesheet. See Refactoring and reviewing XSLT for more on reading and changing a large stylesheet.

XSLT 3.0 and the XSLT 4.0 draft

XSLT 3.0 and XPath 3.1 are fully supported. Features of the XSLT 4.0 and XPath 4.0 drafts that Saxon 13 implements are supported too: record and enum types with type-aware checks, xsl:switch with quick fixes for missing cases, keyword arguments, and path expressions that navigate JSON.

Everything described here is in the user guide: editing XSLT and XPath, code navigation, XML catalogs and XSLT packages.

Common questions

Can Visual Studio Code edit XSLT?

Yes. VS Code edits any XML, and the XSLT/XPath extension adds XSLT-aware checking, completion, hover help, navigation and refactoring for XSLT 3.0 and the XSLT 4.0 features of Saxon 13.

Does the editor check XPath expressions?

Yes. The XPath in attributes and text value templates is checked for syntax, types, function arguments and unused or unresolved variables as you type.

Does it support XSLT 4.0?

It supports the XSLT 4.0 and XPath 4.0 features implemented in Saxon 13, such as records, enums, xsl:switch, keyword arguments and JSON path expressions.
